1情境

部落格平台的首頁要列出所有部落格的網址。資料都在資料庫的 Blogs 表裡，你要怎麼跟資料庫說「把它們給我」？

跟資料庫溝通的語言是 SQL，所以先學 SQL 怎麼說，再看 EF Core 怎麼幫你說。

2先學 SQL：SELECT 句型

從資料庫讀取資料，用的是 SELECT。最基本的句型只有兩個空格要填：

SELECT * FROM Blogs;            -- 從 Blogs 表拿「全部欄位」
SELECT BlogId, Url FROM Blogs;  -- 從 Blogs 表只拿 BlogId 和 Url 兩個欄位
SQL 的幾個小規則

關鍵字大小寫都可以（select = SELECT，習慣上用大寫）。結尾的分號可省略。-- 後面是註解。沒有寫條件時，會拿回表裡的每一列；只拿部分列的寫法是下一課的 WHERE。

3SQL ↔ LINQ 對照

以下 6 個例子，「EF Core 產生的 SQL」和「結果」都是 dotnet run -- L01 實際執行的輸出。

① 取出整張表
SQL 
SELECT * FROM Blogs;
LINQ 
var blogs = db.Blogs.ToList();
// 型別：List<Blog>
EF Core 產生的 SQL

FROM [Blogs] AS [b]

db.Blogs 就是 Blogs 表，ToList() 是「現在就去查，把結果裝成 List」。EF Core 不會送出 SELECT *，而是把 Blog class 的每個欄位都列出來；[b] 是它幫資料表取的別名。

② 只取需要的欄位
SQL 
SELECT BlogId, Url FROM Blogs;
LINQ 
var list = db.Blogs
    .Select(b => new { b.BlogId, b.Url })
    .ToList();
EF Core 產生的 SQL 
SELECT [b].[BlogId], [b].[Url]
FROM [Blogs] AS [b]

Select 對應 SQL 的 SELECT 欄位清單：b => 的 b 代表「每一列」，new { … } 寫幾個屬性，SQL 就只查幾個欄位。這種只挑部分欄位的做法叫投影（Projection）。注意順序變了，原因見第 5 節。

③ 欄位改名
SQL 
SELECT Url AS Address, Rating
FROM Blogs;
LINQ 
db.Blogs
  .Select(b => new { Address = b.Url, b.Rating })
  .ToList();
EF Core 產生的 SQL 
SELECT [b].[Url] AS [Address], [b].[Rating]
FROM [Blogs] AS [b]

SQL 用 AS 取別名，LINQ 用 新名字 = 屬性。

④ 計算出來的欄位
SQL 
SELECT Title,
       LEN(Title) AS TitleLength,
       Views * 2  AS DoubleViews
FROM Posts;
LINQ 
db.Posts.Select(p => new
{
    p.Title,
    TitleLength = p.Title.Length,
    DoubleViews = p.Views * 2
}).ToList();
EF Core 產生的 SQL 
SELECT [p].[Title], CAST(LEN([p].[Title]) AS int) AS [TitleLength],
       [p].[Views] * 2 AS [DoubleViews]
FROM [Posts] AS [p]

C# 的 .Length 被翻成 SQL Server 的 LEN()，在資料庫端算好才傳回來。

⑤ 只要一個欄位
SQL 
SELECT Name FROM Authors;
LINQ 
List<string> names = db.Authors
    .Select(a => a.Name)
    .ToList();

結果：["小明", "小華", "阿傑"]。Select 裡只寫一個屬性（沒有 new { }），得到的就是該型別的清單，不是物件清單。

⑥ 投影成自己定義的類別（DTO）
SQL 
SELECT BlogId, Url FROM Blogs;
LINQ 
public record BlogSummary(int Id, string Url);

db.Blogs
  .Select(b => new BlogSummary(b.BlogId, b.Url))
  .ToList();

SQL 和 ② 一樣，差別只在 C# 端拿到的是有名字的型別 List<BlogSummary>。API 回傳給前端時，通常就是回傳這種 DTO（Data Transfer Object）。

4為什麼「只取需要的欄位」比較好

首頁只需要網址，但 ① 會把每個欄位都拿回來。想像 Posts 表有一個很長的 Content（整篇文章內容），列表頁卻只要標題：

好處說明
傳得少、比較快資料庫少讀、網路少傳、記憶體少用。資料量大時差很多
不會被追蹤取整個 Entity 時，EF Core 會記住它們以便之後存檔（入門文件第 8 節）。投影出來的匿名型別或 DTO 不會被追蹤，省下這份工作（L15 會再講）
API 回傳更安全只回前端需要的欄位，不會把不該公開的欄位一起送出去，也不會遇到導覽屬性的循環參考

原則：要修改資料時取整個 Entity；只是要顯示時，用 Select 投影。

5常見的坑

坑 1：沒寫排序，順序就不保證

對照 ① 和 ②：同一張表，① 是 1、2、3，② 卻是 3、1、2。原因是 ② 只要 BlogId 和 Url，SQL Server 發現 Url 上的索引（為了「網址不可重複」建立的）剛好包含這兩個欄位，就直接讀索引，而索引是照網址字母排序的。

重點：沒有 ORDER BY（LINQ 的 OrderBy）時，資料庫可以用任何順序回傳。需要順序就一定要明確寫出來，第 3 課會教。

坑 2：先 ToList() 再 Select 
// ✗ 先把整張表（所有欄位）抓回記憶體，再在 C# 裡挑欄位
db.Posts.ToList().Select(p => p.Title);

// ✓ 先 Select 再 ToList：SQL 只查 Title
db.Posts.Select(p => p.Title).ToList();

ToList() 是「現在就去查」的分界線，它之前的部分會變成 SQL，之後的部分在 C# 記憶體裡執行。所以 Select 要寫在 ToList() 前面。第 6 課會深入講這條分界線。

補充：匿名型別不能當方法的回傳型別

new { b.BlogId, b.Url } 是沒有名字的型別，只能在同一個方法裡用。要從方法或 API 回傳，就改用 ⑥ 的 DTO（record 或 class）。

練習 3（挑戰）　列出每篇文章的標題，以及「有沒有內容」（Content 是否為 NULL）。
提示

SQL 用 CASE WHEN 條件 THEN 值 ELSE 值 END 依條件產生值；判斷 NULL 要用 IS NULL，不能用 = NULL。LINQ 直接寫 p.Content != null。

看答案 
SELECT Title,
       CASE WHEN Content IS NULL THEN 0 ELSE 1 END AS HasContent
FROM Posts;
db.Posts.Select(p => new { p.Title, HasContent = p.Content != null }).ToList();

EF Core 產生的 SQL：

SELECT [p].[Title], CASE
    WHEN [p].[Content] IS NOT NULL THEN CAST(1 AS bit)
    ELSE CAST(0 AS bit)
END AS [HasContent]
FROM [Posts] AS [p]

只有「草稿：Include 心得」是 false。C# 的 bool 在 SQL Server 對應 bit 型別（0 / 1）。
