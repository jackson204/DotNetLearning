1為什麼要一個練習專案？

學查詢最快的方法，是自己執行、看到結果。光看文件，很難知道 Select 到底送出了什麼 SQL、拿回了哪些資料。

所以這個系列配了一個小專案 EfCoreLab：資料庫和範例資料都準備好了，每課的範例只要一行指令就能執行，畫面上會依序印出：

印出的區塊內容
SQL 你會寫的 SQL同一個查詢用 SQL 怎麼寫（教學用的寫法）
LINQ用 EF Core 怎麼寫
EF SQL EF Core 產生的 SQLEF Core 把 LINQ 翻譯成的 SQL，也就是實際送到資料庫的內容
結果資料庫回傳的資料，排成表格

練習專案放在 RiderProjects\DotNetLearning\ef-core\lab，跟這些教學文件在同一個學習 repo 裡。

2把它跑起來

步驟 1：確認有 LocalDB

sqllocaldb info
# 應該看到：MSSQLLocalDB

LocalDB 是給開發用的迷你 SQL Server，不需要另外設定。沒有的話，安裝 SQL Server Express 時勾選 LocalDB。

步驟 2：建立資料庫與範例資料

用 Rider 打開 ef-core/lab/EfCoreLab.sln，在 ef-core/lab/EfCoreLab 資料夾（.csproj 所在處）開終端機：

dotnet run -- reset

看到「資料庫 EfCoreLab 已重建，範例資料已放入。」就完成了。之後練習時改壞了資料，再執行一次 reset 就會回到初始狀態。

步驟 3：執行第一課

dotnet run -- L01

畫面會像這樣（實際執行的輸出）：

══ L01　SELECT 取資料 ↔ ToList / Select 投影 ══

▶ ② 只取需要的欄位：編號和網址
  ┌ 你會寫的 SQL
  │ SELECT BlogId, Url FROM Blogs;
  ┌ LINQ
  │ db.Blogs.Select(b => new { b.BlogId, b.Url }).ToList()
  ┌ EF Core 產生的 SQL（ToQueryString）
  │ SELECT [b].[BlogId], [b].[Url]
  │ FROM [Blogs] AS [b]
  結果：3 筆
    BlogId | Url
    -------+----------------------------
    3      | https://cooking.example.com
    1      | https://devblog.example.com

4兩種看 SQL 的方法

方法一：ToQueryString()

把查詢翻譯成 SQL 字串，但不執行。適合寫程式時快速確認「這段 LINQ 會變成什麼 SQL」。

var query = db.Blogs.Select(b => b.Url);
Console.WriteLine(query.ToQueryString());
// SELECT [b].[Url]
// FROM [Blogs] AS [b]

EfCoreLab 每一段範例的「EF Core 產生的 SQL」就是用它印的。

方法二：記錄（Logging）

在 DbContext 開啟記錄，每次真的送 SQL 到資料庫時都會印出來，還附上花了多少時間。

options.UseSqlServer(connectionString)
       .LogTo(Console.WriteLine,
              new[] { RelationalEventId.CommandExecuted });

EfCoreLab 加上 --log 就會開啟。輸出像這樣：

Executed DbCommand (3ms) [Parameters=[]...]
SELECT [b].[BlogId], [b].[Rating], [b].[Url]
FROM [Blogs] AS [b]
差別在哪？

ToQueryString() 只看單一查詢的翻譯結果；記錄則會抓到所有實際送出的 SQL。之後學 N+1 問題時，你會靠記錄發現「明明只寫一行，卻送了 11 次 SQL」。在 ASP.NET Core 專案裡，把 appsettings.Development.json 的 Microsoft.EntityFrameworkCore.Database.Command 設成 Information，效果就跟方法二一樣。

5在 Rider 裡直接執行 SQL

學 SQL 的時候，直接對資料庫執行最快。每課都有一個 Lessons/Lxx.sql：

  1. Rider 右側打開 Database 視窗 → + → Data Source → Microsoft SQL Server LocalDB。
  2. Instance 選 MSSQLLocalDB，驗證方式用 Windows 驗證，資料庫選 EfCoreLab，按 Test Connection 後確定。第一次可能會提示下載驅動程式，照著按就好。
  3. 打開 Lessons/L01.sql，右上角選剛才的資料來源。
  4. 把游標放在某一段 SQL 上（或選取它），按 Ctrl+Enter 執行，下方會出現結果表。

也可以在 Database 視窗對資料庫按右鍵 → New → Query Console，自由輸入 SQL 試試看。

練習 2　在 Rider 的 Query Console 執行 SELECT * FROM Posts;，數數看有幾筆、哪幾篇的 AuthorId 是 NULL。
看答案

10 筆。AuthorId 為 NULL 的是第 7、9、10 篇（AsNoTracking 何時用、番茄炒蛋、三杯雞）。

練習 3　執行 SELECT * FROM PostTag;，這張表是做什麼的？
看答案

它是文章與標籤多對多關係的中間表，每一列代表「某篇文章有某個標籤」，欄位是 PostsPostId 和 TagsTagId。EF Core 自動建立，C# 裡沒有對應的 class。第 10 課會詳細講。
